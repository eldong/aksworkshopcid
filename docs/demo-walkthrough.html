Meet the application

Establish that application complexity is intentionally low.

Static frontend

Home, About, and Contact pages built with HTML, CSS, and Bootstrap.

Nginx container

A small `nginx:1.27-alpine` image serves the files over port 80.

Two replicas

Kubernetes maintains two pods with readiness, liveness, and resource controls.

Show the workload
kubectl get deployment aks-static-website
kubectl get pods --selector app=aks-static-website --output wide
kubectl describe deployment aks-static-website
Talk track

"Because the app has no backend or database, every moving part we see is about packaging, delivery, availability, and traffic management."

Key teaching points

  • Kubernetes asks Azure for a Layer 4 load balancer.
  • The Service exposes one public IP and port.
  • The selector routes to healthy website pods.
  • This is easy and effective for one simple service.
Live test Open the current Service external IP and navigate through all three pages.
Talk track

"A LoadBalancer Service is the quickest route from the internet to one Kubernetes service. The tradeoff is that each public service can create its own Azure load balancer configuration and it does not provide host or path routing."

5

What the Azure portal created

Walk through the managed AGIC integration before deploying a route.

Azure resources

  • `ingress-appgateway` using Standard_v2
  • Static public IP resource
  • Dedicated `10.225.0.0/24` subnet
  • AGIC managed identity
  • Network Contributor on the node resource group

Kubernetes resources

  • `ingress-appgw-deployment` in `kube-system`
  • `azure-application-gateway` IngressClass
  • Existing NGINX class remains installed
  • No Ingress exists until the optional workflow runs
Inspect AGIC
kubectl get deployment ingress-appgw-deployment `
  --namespace kube-system

kubectl get ingressclass --output wide
kubectl get ingress --all-namespaces
Ownership warning AGIC treats Kubernetes Ingress as the source of truth and can overwrite listeners, pools, rules, settings, and probes edited manually on its gateway.
6

Deploy the Application Gateway Ingress

Use the isolated manual workflow only after the gateway is running.

The Kubernetes route

k8s/agic/ingress.yaml
spec:
  ingressClassName: azure-application-gateway
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: aks-static-website
                port:
                  number: 80

Run the workflow

  1. Open GitHub Actions.
  2. Select Deploy AGIC Ingress.
  3. Choose Run workflow on `main`.
  4. Watch AGIC controller readiness.
  5. Watch the Ingress address appear.
  6. Open the tested endpoint.
Why a separate workflow? The base CD workflow intentionally does not recurse into `k8s/agic/`. Application releases remain independent from optional ingress configuration.
Observe reconciliation
kubectl get ingress aks-static-website --watch
kubectl describe ingress aks-static-website

az network application-gateway show-backend-health `
  --resource-group MC_rg-aks-workshop_aks-workshop_eastus `
  --name ingress-appgateway `
  --output table
Talk track

"The workflow creates only a Kubernetes Ingress. AGIC observes it and programs the Azure gateway. This is the control loop that connects Kubernetes intent to Azure infrastructure."

Discussion prompt

Ask the audience which path they would choose for a single service, and when host routing, path routing, centralized TLS, or WAF would justify an ingress gateway.

8

Wrap-up and rollback

Finish with the operational model and a safe reversal path.

What students learned

  • How a LoadBalancer Service exposes a workload
  • How GitHub OIDC removes stored Azure credentials
  • How immutable image tags flow from CI to CD
  • How AGIC translates Ingress into gateway configuration
  • Why the two traffic paths can coexist

Application rollback

Remove only the optional route
kubectl delete --filename k8s/agic/ingress.yaml
kubectl get service aks-static-website --output wide

The original LoadBalancer Service remains available.

Do not use application rollback to delete infrastructure Disabling the AGIC add-on or deleting Application Gateway, its subnet, identity, or public IP requires a separate reviewed cleanup plan.
Closing line

"We started with one public Kubernetes Service, automated its releases, and then layered in application-aware routing while preserving a working fallback."
