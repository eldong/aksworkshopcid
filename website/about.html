About the project

A transparent path to Kubernetes.

Each part is intentionally small, readable, and ready to discuss in class.

The goal

Learn the delivery flow without application complexity.

The website has no backend, database, or runtime configuration. That keeps the focus on the essential cloud-native concepts: images, registries, declarative manifests, identities, and rollouts.

Every push to the main branch produces a uniquely tagged image. A successful build then starts deployment of that exact image to the existing AKS cluster.

Technology stack

WebsiteHTML, CSS, Bootstrap
Web serverNginx
RegistryAzure Container Registry
PlatformAzure Kubernetes Service
AutomationGitHub Actions
Delivery stages

One change, three clear stages

1

Package

Docker copies the website into a small Nginx image.

2

Publish

CI tags the image with its run number and pushes it to ACR.

3

Roll out

CD applies the manifests and waits for Kubernetes to complete the rollout.
